NoAS

每天自动重建的广告 / 追踪 / 恶意域订阅。全部跑在 GitHub 自家免费能力上，不依赖任何第三方平台。

直接接入（一条订阅）

只做 DNS 层：广告/追踪/威胁域名进黑名单，正常业务域名进白名单，智能识别自动维护。 订阅地址：/subs/all/adguard.txt（AdGuard for Android / AdGuard Home / Pi-hole / mosdns / sing-box 等 DNS 类客户端直接导入）； 纯域名版 /subs/all/domains.txt，白名单 /subs/all/whitelist.txt。

自建 DoH（不需要任何服务器租用）

本仓库自带零依赖 DoH 服务，规则与订阅同源，不会出现"订阅拦了但 DoH 没拦"：

  • python3 tools/build_doh.py 生成 doh/worker.js
  • node serve/standalone.mjs 起服务，/dns-query 收 DoH，/check 查单域，/health 看状态
  • 端点表优先于白名单：百度 / 腾讯 / 谷歌的广告投放端点即使父域在白名单里也照拦

发布前必须过的闸

  • 七个格式条数完全一致，meta 里 sha256 与真实文件对得上
  • 命中白名单（含父域）的一律剔除；台账 lists/whitelist.tsv 只增不减，误报留痕
  • 比上一轮少 15% 以上直接停发（宁可停一天，也不发残包）
  • 回归用真产物跑：lite 全量逐条必须拦、mid 抽样必须拦、良性域必须放行，漏放/误拦不为 0 就不发

自我成长

每天体检一次源：连续失联的自动淘汰，候选池里达标（≥300 条、可解析、与台账零冲突）的自动吸收；每周自动发现新源；仓库 Issue 即错误报告接口（标签 误伤 / 漏拦），误伤自动进白名单立刻放行、漏拦只收带广告结构的端点，其余进观察池等共识。全过程写入 history/growth.json 与 learn_events.jsonl，可逐日审计。

边界（不吹）

DNS 层做不到"百分百"：同域多租户路径广告、加密 SNI、客户端自带 DoH 都能绕过 DNS 拦截。本项目的做法是把公开源并集拉满、把审计过的广告端点强制入档、白名单硬闸只放过真正需要放过的域——DNS 层能拦的，不放过。
