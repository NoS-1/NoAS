四层叠加去广告

先说结论：任何单层都做不到 100%。能做到"接近全场景"的只有四层叠加，且每层上限不同。

L1 · DNS
域名层

拦第三方广告/追踪域名。覆盖所有 App 与设备，但拦不住同域广告与服务端注入。

lite · adguard.txt Pages 镜像入口

真实上限：App 内广告约 70%–85%。

L2 · 路径
接口层（本页新增）

对 HTTPS 解密后按 URL 正则拦开屏/广告接口。国内 App 开屏广告的主力解法。

Surge / Shadowrocket（模块）

core · noas-path.sgmodule（保守，14 条） full · noas-path.sgmodule（19 条 + 37 主机）

Loon（插件）

core · noas-path.plugin full · noas-path.plugin

QuantumultX（重写）

core · noas-path.conf full · noas-path.conf

需要 MITM 并信任证书；证书固定的 App 会直接断连，此时把该主机从 MITM 列表里删掉即可。core 每条都锚定具体主机，不会波及其他 App。

真实上限：国内 App 开屏/信息流约 90%–95%。

L3 · 内容
页内层（本页新增）

浏览器扩展用，隐藏广告位、拦广告脚本。DNS 拿不到的页面级广告由这层兜。

uBO 自定义规则 · noas-ubo.txt

用法：uBO → 过滤器列表 → 导入自定义列表，粘贴上面地址。Chrome/Edge 因 MV3 只剩 uBOL，能力明显缩水；要满血请用 Firefox + 经典 uBO。一个浏览器只装一个拦截器，别叠两个。

真实上限：网页横幅/追踪约 98%，YouTube 网页端会反复"失效—修复"。

L4 · 交互
点击层（Android）

网络层拦不到的 App 开屏，用无障碍自动点"跳过"。这是唯一能对付"同域广告"的免费办法。

GKD 规则订阅

GKD 需要无障碍权限，只从官方仓库装。iOS 没有对应方案：苹果不允许第三方点击 App 界面，别信"快捷指令跳过开屏"的教程。

补充：安卓系统级还可用 AdAway（F-Droid 免费，无需 root 走本地 VPN），源填本站 hosts.txt。

绕过与排障

现象原因处理
DNS 层明明拦了，Chrome 还是出广告Chrome 自带"安全 DNS"走了自己的 DoH，绕过你的解析Chrome → 设置 → 隐私与安全 → 安全 DNS → 改回"使用当前服务商"
iPhone 部分请求不走你的 DNSiCloud 私密转发（Private Relay）自带加密解析Apple ID → iCloud → 私密转发 关闭
安卓在酒店/公司 Wi-Fi 上突然失效网络封了 DoT（853），私有 DNS 掉线后回落明文改用 AdGuard/RethinkDNS 这类本地 VPN 走 DoH；或换网络
开了 L2 某个 App 白屏/登录失败MITM 撞上证书固定，或规则命中过宽把该主机从 mitm.txt 删除；或退回 core 档；必要时删掉对应规则行
App 完全不遵守系统 DNSApp 内置 DoH 端点（自家解析）只能靠 L2 路径层或路由器防火墙封 DoH 端点，DNS 层无解
想确认 L2 到底生效没—Loon/Surge 开请求日志，打开目标 App，看广告接口是否显示 reject；或对比开关前后的开屏时长

怎么用

  • 只想要省事：L1 订阅 + 浏览器装上 uBO（L3）即可，不折腾证书。
  • 要治开屏：L1 + L2 core（Surge/Loon/QX 任一），先只开 core，确认没有 App 异常再换 full。
  • 要拉满：L1 + L2 full + L3 + 安卓 L4。
  • 出现 App 白屏/登录失败：先关 L2，确认是否 MITM 引起；是的话把对应主机从 mitm.txt 移除，或只用 core。
规则每日随主仓重建；路径层条目全部写在 lists/ad_paths.tsv，逐条带 App 与用途，可自行删改。
